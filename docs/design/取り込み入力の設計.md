# 鳴っている音を取り込んで分離する（capture.html）設計書

- **作成日:** 2026-09-14
- **対象:** `capture.html`（新規）、`engine.js`（新規・共通）、`stream.html`（薄くした）
- **既存ページ（`index.html` / `player.html` / `separator-worker.js` / `vendor/*`）は無改変**

---

## 1. 何を作るか / 作らないか

**作る:** 音声入力（PCで鳴っている音・マイク・ライン入力）を取り込み、
分離して立体音響で再生する。入口が変わるだけで、中身は `stream.html` と同じ。

**作らない（明確に）:**

| | 理由 |
|---|---|
| YouTube等からのダウンロード・抽出 | 各サービスの利用規約が禁止している |
| DRM保護された音源の取り込み | **技術的保護手段の回避は私的使用の例外から外れる**。Chrome 側でも遮断され無音になる |
| 特定サービス向けの作り込み | 「音声入力を受ける」一般機能に留める。レコードプレーヤーを繋ぐのと同じ扱い |

**DRMとの関係。** DRM が守るのは配信から復号までの経路で、**音になった後（スピーカー・
Bluetooth）は保護の対象外**である。Bluetooth の A2DP には HDCP のような保護が無い。
ここを録ることは「回避」には当たらない（俗にアナログホールと呼ばれる構造）。
ただし**利用規約は著作権法とは別**であり、そこは利用者の判断に委ねる。
画面にもその旨を明示する。

## 2. なぜ「録ってから」なのか（ライブにしない理由）

**流しっぱなしの分離は R<1 でないと成立しない。**

```
ファイル：  全部手元にある → いくらでも先読みできる      ← stream.html
ストリーム：実時間でしか届かない → 先読みが作れない
```

R=1.37 の端末では毎秒0.37秒ずつ遅れが積み上がり、10分で3分半以上ずれる。
加えて htdemucs は7.8秒ぶんをまとめて見ないと出力できないため、最低8秒は遅れる。

したがって **案A「録る → 分ける → 鳴らす」** を先に作る。
R<1 の端末が確認できれば、同じ土台に **案B「流しっぱなし」** を足せる。

## 3. 共通エンジンへの切り出し

`stream.html` は902行あり、`capture.html` はその大半（分離・先読み再生・立体音響）を
必要とする。**複製すると、片方だけ直した不具合が残る**（この機能では実際に
「暖機」「先読みの式」「resume の扱い」で何度も修正が入っている）。

そこで `engine.js` に切り出した。

| ファイル | 役割 | 行数 |
|---|---|---|
| `engine.js` | 分離・先読み再生・立体音響・暖機・共通UI | 871 |
| `stream.html` | 手元のファイルを渡すだけ | 78（旧902） |
| `capture.html` | 音声入力を録って渡すだけ | 約290 |

エンジンの入口は3つだけ。

```js
initEngine({
  startLabel: '…',
  canStart: () => 音源が用意できているか,
  getAudio: async () => ({ left, right, sampleRate, duration, label }),
});
setReady(boolean);      // 音源が用意できた／できなくなった
engineLog(msg, cls);    // ページ側からログへ
```

共通のCSSと画面（進み具合・音の位置・パート・ログ）は `engine.js` が
`#engine-controls` と `#engine-ui` に差し込む。**HTMLも二重に持たない。**

## 4. 取り込みの作り

### 4.1 取り込み元

| 方法 | API | 用途 |
|---|---|---|
| 入力機器を選ぶ | `getUserMedia({deviceId})` | マイク・ライン入力・**PCで鳴っている音**（Linux/PipeWire では「Monitor of …」として出る） |
| タブ／画面の音 | `getDisplayMedia({audio:true})` | ブラウザで鳴っている音 |

機器名は**一度許可しないと空になる**仕様のため、「許可する」ボタンを先に置く。
`Monitor` を含む機器があれば、それがPCで鳴っている音だと画面で案内する。

**音声の補正はすべて切る**（`echoCancellation` / `noiseSuppression` / `autoGainControl`）。
通話用の補正が入ると音楽が壊れ、分離の質も落ちる。

### 4.2 録音

`MediaRecorder` は使わない（Opusに圧縮され、分離の入力として劣化する）。
**AudioWorklet で生のPCMを集める。** ワークレットは別ファイルにせず Blob URL で持つ。

- 上限10分（`MAX_SEC`）。超えたら自動停止して知らせる
- 取り込んだ音は**ここでは鳴らさない**（元の音と二重再生・ハウリングになるため）
- 停止時に断片を1本に繋ぎ、`{left, right, sampleRate, duration}` にしてエンジンへ渡す

### 4.3 無言で失敗させない

**止まった AudioContext では AudioWorklet の `process()` が呼ばれず、
「録音中」と出たまま1サンプルも取れない。** 実測で11秒録って0.0秒だった。

- `attach()` で `resume()` する（**await しない**。自動再生ポリシーで解決しないことがある）
- 録音開始時に停止状態なら、クリックを促してワンショットで再開する
- **3秒たっても1サンプルも来なければ知らせる**（取り込み元違い／DRM遮断の可能性を提示）
- レベル表示を常時出し、音が来ているかを目で確認できるようにする

## 5. 異常系

| 事象 | 対処 |
|---|---|
| 許可されない | 理由を表示。機器一覧は出さない |
| タブ共有で音声にチェックが無い | 明示して取り込まない（映像だけ掴まない） |
| DRMで無音 | レベル表示が動かない＋停止時に「ほぼ無音」を警告 |
| 取り込み元が終了（タブを閉じた等） | `track.onended` で片付けて表示 |
| 10分を超える | 自動停止して知らせる |
| 録音0秒で分離開始 | `getAudio()` で例外にして知らせる |
