### 見つけて直した不具合：無言で失敗していた

**止まった AudioContext では AudioWorklet の `process()` が呼ばれず、
「録音中」と表示されたまま1サンプルも取れない。** 11秒録って `0.0秒` だった。
しかも画面には理由が何も出ない。

修正後は、同じ状況で次のように知らせる。

```
22:52:17  ブラウザが音の取り込みを止めています。ページのどこかをクリックしてください
22:52:21  3秒たっても音が1つも届いていません。取り込み元が違うか、
          DRMで保護されている可能性があります（レベル表示も確認してください）
```

| 追加した手当て | 内容 |
|---|---|
| `attach()` で `resume()` | **await しない**（待つと自動再生ポリシーで固まる。既知の落とし穴） |
| 録音開始時の停止検知 | クリックを促し、ワンショットで再開 |
| 3秒無音の見張り | 原因の候補（取り込み元違い／DRM）を提示 |
| 停止時の0サンプル | 取り込み状態（`ctx.state`）を添えて知らせる |
| レベル表示 | 常時表示。音が来ているかを目で確認できる |

## 3. 未検証（重要）

| 項目 | 理由 |
|---|---|
| **実際の音を取り込んで分離できるか** | この自動操作環境では**信頼できるクリック（ユーザー操作）を発生させられず**、`AudioContext` が起動しない。合成音を流す側も同じ理由で止まったままだった。**実機での確認が必須** |
| タブ共有（`getDisplayMedia`） | 共有ダイアログが自動操作できない |
| DRM保護時の挙動 | 検証対象を用意できない。Chrome が遮断する想定 |
| 長時間録音（10分）でのメモリ | 未実測。10分ステレオで約212MB になる見込み |
| スマホ | 環境なし |

**実機で最初に確認していただきたいこと**

1. 「許可する」→ 機器一覧に **「Monitor」付きの項目**が出るか（PCで鳴っている音）
2. 音を鳴らして、**レベル表示が動くか**（動かなければ取り込めていない）
3. 数十秒録って停止 → 「録音済み ○秒（最大音量 ○%）」が出るか
4. 分離 → 立体音響で鳴るか
