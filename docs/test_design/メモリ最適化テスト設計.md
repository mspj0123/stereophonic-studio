# ブラウザ内分離のメモリ最適化 テスト設計書

**対象改修**: `docs/design/メモリ最適化設計.md`
**作成日**: 2026-08-17

改修の性質上、**「音質が変わっていないこと」の証明**が最重要。加えて、目的である
**メモリ削減が実際に効いていること**を実測で確認する。

---

## 1. テスト環境

| 項目 | 内容 |
|---|---|
| 実行方法 | `python3 -m http.server 8765` でローカル配信し、Chrome（claude-in-chrome）で操作 |
| 分離方式 | CPU(WASM)・4スレッド（テスト機はGPU非対応のため WebGPU 経路は対象外） |
| テスト音源 | `make_test_wav.py` で生成した合成ステレオWAV（低音／打点／和音／声風を重ねたもの） |
| 音源の長さ | 25秒（機能確認用）、120秒（メモリ測定用） |

> 合成音を使う理由：結果が決定的で再現でき、権利の問題も生じないため。
> ただし**音楽的な聴感の評価は合成音ではできない**ので、実際の楽曲での試聴は別途ユーザーが行う。

---

## 2. 正常系テストケース

| No | 観点 | 手順 | 期待結果 |
|---|---|---|---|
| N-1 | 分離が最後まで通る | 25秒の曲を選択 | 「✅ 分離完了」と表示され、4パートがプレイヤーに追加される |
| N-2 | パートの表示順 | N-1 の結果を見る | 従来どおり vocals / drums / bass / other の順 |
| N-3 | **チャンクの連続性** | Worker のチャンクの offset と length を記録 | 隙間・重複がなく、合計が全長と一致する |
| N-4 | **出力波形の同一性** | 同じ入力を旧実装（`main` の processor.js）と新実装で分離し全サンプル比較 | **差がゼロ**（最大絶対差 0） |
| N-5 | 出力が無音でない | 各パートの RMS を計算 | すべて 0 より大きい |
| N-6 | 分離の妥当性 | 4パートの合計と元音声を比較 | 相対誤差が十分小さい（Demucs は合計≒原音になる） |
| N-7 | 継ぎ目に段差がない | チャンク境界の隣接サンプル差を、境界でない位置の分布と比較 | 境界の値が通常位置の分布に収まる |
| N-8 | モデルのキャッシュ | 1回目の分離後、2回目を実行 | `cachehit` が通知され、ダウンロードが発生しない |
| N-9 | **メモリ削減** | 120秒の曲で新旧それぞれのピークメモリを実測 | 新実装のピークが旧実装より明確に小さい |
| N-10 | 進捗表示 | 分離中の表示を確認 | 進捗％・パート番号・経過時間が更新され続ける（UIが固まらない） |

## 3. 異常系テストケース

| No | 観点 | 手順 | 期待結果 |
|---|---|---|---|
| E-1 | 曲が長すぎる | 上限（10分）を超える音源を選択 | 分離を開始せずエラー表示。ブラウザは落ちない |
| E-2 | 低メモリ端末の上限 | `navigator.deviceMemory` を 4 に偽装して 5分超の音源を選択 | 5分の上限が適用されエラー表示 |
| E-3 | 低メモリ端末の警告 | `navigator.deviceMemory` を 4 に偽装してページを開く | 「5分以内の曲まで」の警告が表示される |
| E-4 | 音声でないファイル | テキストファイルを選択 | デコード失敗として日本語のエラーが表示され、UIが操作可能に戻る |
| E-5 | Cache API が使えない | `caches.open` が例外を投げる状況を再現 | 素の fetch にフォールバックして分離が完走する |
| E-6 | キャッシュ保存の失敗 | `cache.put` が例外を投げる状況を再現 | 分離は正常に完走する（保存失敗は無視される） |
| E-7 | モデル取得の失敗 | 存在しないモデルURLを指定 | HTTPステータスを含む日本語エラーが表示される |
| E-8 | Content-Length が無い | ヘッダ無しのレスポンスを再現 | `arrayBuffer()` にフォールバックして完走する |
| E-9 | 分離中のWorkerエラー | Worker から error を返させる | UIにエラーが表示され、ボタンが再操作可能に戻る |
| E-10 | 連続実行 | 分離を2回続けて実行 | 2回目も正常に完了する（状態が残らない） |

## 5. 実施しないもの（理由を明記）

| 項目 | 理由 |
|---|---|
| WebGPU 経路の実測 | テスト機にGPUが無く `requestAdapter()` が null。ユーザー実機での確認が必要 |
| スマホ実機での確認 | 手元に実機が無い。ユーザー確認が必要 |
| 実楽曲での聴感評価 | 権利の都合でテスト用に配置できない。N-4（波形完全一致）で音質不変は保証されるため、
聴感の最終確認はユーザーが手持ちの曲で行う |
| メモリ不足クラッシュそのものの再現 | 意図的なOOMはブラウザごと落ちるため自動テストにできない。緩和策の効果はN-9で代替評価する |
