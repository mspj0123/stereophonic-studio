# 分離結果の保存（作業フォルダ）と曲リスト テスト設計書

**対象**: `d-browser-app/index.html`（テスト実施時のファイル名は `player.html`）
**作成日**: 2026-09-06
**設計書**: `docs/design/分離結果の保存と曲リスト設計.md`

---

## 1. テスト方針

- **E2E（実ブラウザ）を主とする**。保存はブラウザAPIに強く依存するため、モックでは意味が薄い。
- **書き出したファイルは、ブラウザの外（Python / `wave` モジュール）で開いて検証する**。
  「エラーが出なかった」ではなく「正しいWAVとして読める」ことを合格条件にする。
- OSのフォルダ選択ダイアログは自動操作できないため、**OPFS（ブラウザ内ファイルシステム）の
  ディレクトリハンドルを `showDirectoryPicker()` の戻り値として差し替える**。
  OPFS のハンドルは `FileSystemDirectoryHandle` そのもので、`getFileHandle` /
  `createWritable` / `entries` / `queryPermission` が同じように動くため、
  **アプリ側のコードを一切変えずに**保存経路を検証できる。
- 正常系だけでなく、`CLAUDE.md`「異常系設計・テストルール」に沿って異常系を必ず含める。

## 2. テスト環境

| 項目 | 内容 |
|---|---|
| ブラウザ | Chrome（claude-in-chrome で自動操作）※GPU無しのためWASM経路 |
| 配信 | `python3 -m http.server` 相当のローカルサーバ（`localhost` は secure context 扱い） |
| テスト音源 | Python で生成した10秒のステレオWAV（110Hz + 440/554Hz + 0.5秒ごとの80Hz打点） |
| 検証手段 | `wave` モジュールでヘッダ・長さ・振幅を確認、`md5` で同一性を確認 |

## 3. 正常系テストケース

| No | 観点 | 手順 | 期待結果 |
|---|---|---|---|
| N-1 | 初期表示 | ページを開く | 「曲:」が `— まだ曲がありません（…）—` で `disabled`。作業フォルダは未設定表示 |
| N-2 | 作業フォルダの選択 | 「📂 作業フォルダを選ぶ」 | 保存先名が表示され、「🔄 一覧を更新」「解除」が出る。空フォルダなら「まだ曲がありません」 |
| N-3 | 分離＆自動保存 | 曲を選んで分離 | `<作業フォルダ>/<曲名>/` が作られ、`source.wav` と4パートが保存される。完了メッセージに保存先が出る |
| N-4 | 保存されたWAVの正当性 | 保存物を取り出して検証 | 16bit / 44.1kHz / ステレオ / 元曲と同じ長さ。無音でない |
| N-5 | 元の曲のコピー | `source.wav` を検証 | 入力ファイルと **md5 が一致**（無劣化コピー） |
| N-6 | 曲リストへの反映 | 保存直後 | 「曲:」に `曲名（4パート）` が追加され、その曲が選択状態になる |
| N-7 | 再訪時の復元 | ページを再読み込み | 前回の作業フォルダが自動で使われ、曲一覧が復元される |
| N-8 | 保存済みの曲を再生 | 一覧から選ぶ | 分離せずに4パートが読み込まれ、再生できる。`source.wav` はパートに含めない |
| N-9 | 立体音響 | 3DトグルON→再生 | `threeDGain=1` / `directGain=0` になり、再生位置が進む |
| N-10 | 曲の置き換え | 曲を読み込んだ状態で別の曲を分離 | トラックが4本のまま（前の曲が残らない） |
| N-11 | 作業フォルダの解除 | 「解除」 | 一覧が空になり、フォルダの中身は削除されない |

## 4. 異常系テストケース

| No | カテゴリ | 観点 | 手順（障害の注入方法） | 期待結果 |
|---|---|---|---|---|
| E-1 | 書き込み失敗 | 保存先に書けない | `getDirectoryHandle` が `NotAllowedError` を投げるよう差し替え | `❌ 作業フォルダへの保存に失敗しました: …` を表示し、**ダウンロードボタンに切り替わる**。分離結果は失われない |
| E-2 | データ保護 | 同名の曲を再分離 | 同じ曲をもう一度分離 | `曲名 (2)` が新規作成される。既存フォルダは変更されない |
| E-3 | 文字種 | 使えない文字を含む曲名 | `ダミー曲/名前:テスト.wav` で保存 | `ダミー曲_名前_テスト_bass.wav` のように `_` へ置換される |
| E-4 | 権限 | 再訪時に許可が切れている | `queryPermission` が `prompt` を返す状態 | 「📂 前回のフォルダを使う（名前）」ボタンが出て、1クリックで復帰できる |
| E-5 | 中断 | フォルダ選択のキャンセル | ダイアログを閉じる（`AbortError`） | エラー表示を出さず、静かに元の状態へ戻る |
| E-6 | 非対応ブラウザ | File System Access API 無し | `showDirectoryPicker` を未定義にして読み込む | 作業フォルダUIが隠れ、案内文が非対応向けに変わる。ダウンロード保存で代替できる |
| E-7 | 入力データ | 音声以外が混ざるフォルダ | `readme.txt` を含むフォルダを読み込む | 音声ファイルだけを対象にする |
| E-8 | 入力データ | 音声が1つも無いフォルダ | 音声を含まないフォルダを読み込む | `⚠ 音声ファイルが見つかりませんでした` を表示（例外にしない） |
| E-9 | 複数曲 | 複数の曲フォルダをまとめて選択 | `親/曲A/…`, `親/曲B/…` を選ぶ | 曲ごとのボタンが出て選べる。勝手に全部読み込まない |
| E-10 | 多重操作 | 書き出し中に連打 | ボタンを連続クリック | 2重実行されない（ボタンが `disabled` になる） |
| E-11 | メモリ | 書き出しでメモリを食い潰さない | 保存中のJSヒープを観察 | 曲全長ぶんの配列を確保していないこと（設計どおりチャンク処理） |
| E-12 | ログ | 想定外の例外 | 全操作後にコンソールを確認 | 意図的に注入したもの以外のエラーが出ていない |

## 5. 合格条件

- 正常系 N-1〜N-11 がすべて期待どおり。
- 異常系 E-1〜E-12 がすべて期待どおり（**落ちない・データを壊さない・原因が画面に出る**）。
- 保存されたWAVが Python で正しく読め、元曲のコピーは md5 一致。
- コンソールに意図しないエラーが出ていない。
