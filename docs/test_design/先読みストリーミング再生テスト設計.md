# 先読みストリーミング再生 テスト設計

- **作成日:** 2026-09-14
- **対象:** `stream.html`
- **設計書:** `docs/design/先読みストリーミング再生設計.md`

---

## 1. 方針

この機能の価値は「**途切れずに、早く鳴り始めること**」にある。したがって
「音が出た」だけでは合格にせず、次の3つを必ず数字で見る。

1. **スタベーション回数が0であること**（途切れていないこと）
2. **再生開始が分離完了より明確に早いこと**（従来より速いこと）
3. **既存ページに影響が出ていないこと**（`git diff` が空であること）

また、**分離速度 R は端末によって変わる前提**で、固定値を期待値にしない。
実測した R に対して、先読み量が理論式どおりに決まっているかを見る。

---

## 2. 正常系

| # | 観点 | 期待 |
|---|---|---|
| N-1 | ページが読める | エラーなく表示。`crossOriginIsolated` と WebGPU 可否が画面に出る |
| N-2 | 分離が始まる | モデル読み込み → 分離中 とフェーズが進む |
| N-3 | R が実測される | 2チャンク目以降に数値が出る（固定値でない） |
| N-4 | 先読み量が式どおり | `need ≒ L × (1 − 1/(R×1.15))`、下限 12秒 |
| N-5 | **分離完了を待たずに再生が始まる** | 再生開始 < 分離完了。ログに先読み量が残る |
| N-6 | **実際に音が出ている** | master の peak/rms が0でない |
| N-7 | **途切れない** | スタベーション0回で最後まで再生 |
| N-8 | 立体音響の切替 | ON/OFF で出力が変わり、戻すと元に戻る |
| N-9 | パートの消音 | `volumeGain` が 1 → 0 → 1 |
| N-10 | パートの音量 | スライダー50% で `volumeGain = 0.5` |
| N-11 | 定位 | `PannerNode` の座標が設計の配置と一致 |

## 3. 異常系

| # | 観点 | 期待 |
|---|---|---|
| E-1 | 分離が再生に追いつかない | `suspend()` で止めて貯め直す。音を割らない |
| E-2 | 3回以上のスタベーション | 先読み量を1.5倍に増やす |
| E-3 | 先読みが120秒を超える | メモリ警告をログに出す |
| E-4 | WebGPU で失敗 | CPU に自動で切り替えて再試行 |
| E-5 | 音声でないファイル | `decodeAudioData` の失敗を捕捉して案内 |
| E-6 | 途中で停止 | Worker を terminate、AudioContext を close |
| E-7 | WebGPU 非対応端末 | チェックボックスを無効化し、理由を表示 |
| E-8 | `crossOriginIsolated` が false | 警告を出したうえで続行 |

## 4. 影響範囲（最重要）

| # | 観点 | 期待 |
|---|---|---|
| R-1 | **既存ファイルを1つも変更していない** | `git diff --stat` が空 |
| R-2 | 既存ページが従来どおり動く | `index.html` がエラーなく表示され、要素が揃っている |
| R-3 | グローバルを汚していない | `index.html` 側に `__stream` などが生えていない |
| R-4 | Worker を改変していない | `separator-worker.js` が差分なし |

## 5. 未実施として残すもの

- **WebGPU 経路**（テスト機にGPUが無い）。R が1を下回る想定だが**未検証**
- **実楽曲での聴感**（合成音では分離の良し悪しが判断できない）
- **長尺（4分以上）**。先読みが長くなりメモリが増えるため、実測が要る
- **スマホ実機**
